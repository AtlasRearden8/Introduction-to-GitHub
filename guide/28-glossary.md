# Chapter 28: Glossary 📖

Every term in plain English, in alphabetical order. Don't try to memorize these. Look things up whenever you need.

---

**Actions (GitHub Actions)**: GitHub's built-in automation. It runs tasks, like tests or website builds, when something happens in a repo.

**Alert (Markdown)**: A special quote block, such as `> [!NOTE]`, that GitHub draws as a colored callout box.

**Alt text**: A short description of an image, read aloud by screen readers and shown if the picture can't load.

**Archive (a repository)**: Make a repository read-only to show it's finished or no longer maintained. Find it under Settings, in the Danger Zone.

**Assignee**: The person responsible for an issue or pull request.

**Author**: The person who made a commit or opened a pull request.

**Badge**: A small status image on a README, such as one showing whether a workflow is passing.

**Base branch**: In a pull request, the branch the changes will be merged *into*, usually `main`.

**Blame**: A GitHub view that shows who last changed each line of a file, and when.

**Branch**: A separate line of work inside a repo, so you can try things without affecting the main version.

**Cite (CITATION.cff)**: A file that adds a Cite this repository button, so others can credit your work correctly.

**Clone**: Download a complete copy of a repository, with its history, to your computer.

**Codespace**: A development environment hosted in the cloud and opened in your browser.

**Collaborator**: Someone you've given access to work directly in your repository.

**Commit**: A saved snapshot of your project, with a short message. The basic unit of history.

**Compare branch**: In a pull request, the branch that contains your new changes.

**Conflict (merge conflict)**: What happens when two sets of changes touch the same lines, and a person has to choose the result.

**Contributor**: Anyone who adds to a project.

**Cron**: A short code that says when a scheduled workflow should run, like `0 9 * * 1` for Mondays at 9:00 UTC.

**Default branch**: The branch GitHub shows first and treats as the main version, usually `main`.

**Dependabot**: A GitHub feature that warns you about out-of-date or unsafe tools your project depends on, and can suggest updates.

**Dependency**: A tool or library that your project relies on.

**Diff**: A comparison showing what changed between two versions. Added lines are green, and removed lines are red.

**Directory**: Another word for a folder.

**Discard**: Throw away changes you haven't committed yet. In GitHub Desktop, right-click a file and choose **Discard Changes...**

**Discussion**: A forum-style conversation on a repository, for questions and ideas that aren't tasks.

**Draft pull request**: A pull request marked as unfinished and not ready for review or merging.

**Event (Actions)**: Something that starts a workflow, such as a push, a new issue, or a schedule.

**Fast-forward**: A merge where the branch simply slides forward, because no one else has added anything new.

**Fetch**: Check GitHub for new work without changing your files. In GitHub Desktop, **Fetch origin**.

**Fork**: Your own copy of someone else's repository, stored in your GitHub account.

**Front matter**: A few lines at the very top of a Markdown file, between two `---` lines, that give a page its title and settings.

**Gist**: A tiny repository for sharing a snippet or note.

**Git**: The free tool that tracks changes to your files and remembers every version. GitHub Desktop uses it for you.

**GitHub**: The website that stores Git projects online and adds tools for working with other people.

**GitHub Desktop**: The free app that lets you use Git and GitHub from your computer by clicking buttons.

**GitHub Pages**: Free website hosting straight from a repository.

**`.gitignore`**: A file listing the files and folders that should *not* be tracked. In GitHub Desktop, right-click a file and choose **Ignore file**.

**Good first issue**: A label that marks an issue as suitable for newcomers.

**Head branch**: In a pull request, another name for the branch that holds your changes.

**Hosting**: Storing something on a server so it's available online.

**Issue**: A trackable item (a bug, task, idea, or question) attached to a repo.

**Jekyll**: The tool GitHub Pages uses to turn Markdown files and a theme into a website.

**Job (Actions)**: A group of steps in a workflow that run together on one computer.

**Label**: A colored tag on issues and pull requests, such as `bug` or `documentation`.

**License**: A file stating what other people are allowed to do with your project.

**Local**: On your own computer, as opposed to *remote*.

**Main**: The usual name of a repo's primary branch. (Older repos may use `master`.)

**Maintainer**: A person responsible for a project, who reviews and merges contributions.

**Markdown**: A simple way of formatting text with symbols like `#` and `**`, used all over GitHub.

**Merge**: Combine changes from one branch into another.

**Merge commit**: A commit that joins two lines of work.

**Milestone**: A named goal that groups issues and pull requests, often with a due date.

**Open source**: A project whose files are public, and which anyone may use or improve under a license.

**Organization**: A shared GitHub account for groups, with teams and permissions.

**Origin**: The nickname for your GitHub copy of a repository. It appears in buttons like **Fetch origin** and **Push origin**.

**Passkey**: A way to sign in with your fingerprint, face, or device PIN instead of a password. Harder to steal or trick.

**Personal access token (PAT)**: A password-like key some tools use to reach GitHub. You don't need one for anything in this guide, and you should never share one.

**Pinned repository**: A repository highlighted as a card near the top of your profile.

**Private repository**: A repository only you and the people you invite can see.

**Public repository**: A repository anyone on the internet can see.

**Publish**: Send a project or branch to GitHub for the first time. In GitHub Desktop, **Publish repository** or **Publish branch**.

**Pull**: Bring new work from GitHub down into your computer. In GitHub Desktop, **Pull origin**.

**Pull request (PR)**: A proposal to merge one branch into another, with a page for discussion and review.

**Push**: Send your saved commits from your computer up to GitHub. In GitHub Desktop, **Push origin**.

**Push protection**: A GitHub safeguard that can block a push when it detects a password or key in your files.

**README**: The front-page file (`README.md`) that describes a project.

**Recovery codes**: One-time codes that let you into your account if you lose your second-factor device. Save them somewhere safe.

**Release**: A packaged, named version of a project on GitHub, such as `v1.0.0`.

**Remote**: A copy of a repository kept somewhere else, such as on GitHub.

**Repository (repo)**: A project folder that Git tracks, including its whole history.

**Resolve (a conflict)**: Choosing the final content when two changes collide.

**Revert**: Make a new commit that cancels an earlier one. It's the safe way to undo shared work.

**Review**: Reading a pull request and responding with comments, approval, or requested changes.

**Runner**: The computer, provided by GitHub, that carries out a workflow.

**Secret**: A password, key, or token that proves who you are. Never put one in a file you commit.

**Secret scanning**: A GitHub feature that watches for passwords and keys committed by accident.

**Session**: A device or browser you're signed in on. Review yours under Settings → Sessions.

**SHA / hash**: The long ID of a commit. Rarely needed when using GitHub Desktop.

**Squash**: Combine several commits into one.

**Stage / Staging area**: In GitHub Desktop, the ticking of checkboxes decides what goes into your next commit. You never need to stage by hand.

**Star**: A bookmark-and-applause button on repositories.

**Stash**: Temporarily put unsaved changes aside so you can switch branches. GitHub Desktop does this when you choose **Leave my changes**.

**Step (Actions)**: A single task inside a workflow job.

**Suggested change**: A review comment that proposes exact replacement text the author can accept with one click.

**Summary**: The short description you write when you commit in GitHub Desktop.

**Sync fork**: A button on GitHub that brings your fork up to date with the original project.

**Tag**: A label pinned to a specific commit, often a version number.

**Template repository**: A repository you can copy as a starting point with the Use this template button.

**Terminal / command line**: A text window where people type commands. Optional. This guide never needs it.

**Topic**: A keyword tag on a repository that helps people find it.

**Triage**: Sorting through issues: labeling, answering, and deciding what to do next.

**Two-factor authentication (2FA)**: Signing in with your password plus a second proof, like a code from your phone.

**Upstream**: The original project that a fork came from.

**Verified (badge)**: A label on a commit showing that GitHub could confirm who made it.

**Version control**: Systems that record changes over time so you can bring back any version.

**Viewed (checkbox)**: A tick in a pull request's Files changed tab that marks a file as reviewed.

**Visibility**: Whether a repository is public or private.

**Watch**: Subscribe to notifications about a repository.

**Wiki**: A set of linked documentation pages attached to a repository.

**Workflow**: A GitHub Actions automation file, or in general, a way of working (as in "GitHub flow").

**Working folder**: The actual files and folders you see and edit on your computer.

**YAML**: A simple text format used for GitHub Actions workflow files and theme settings. Indentation matters.
