# Chapter 31: Resources & Where to Go Next 🗺️

🎯 **Goals:** Find the best free places to keep learning, get help when you're stuck, and grow your skills in whichever direction excites you.

> 💡 Websites and offers change. If a link has moved, search for the name. Everything here is free or has a free option unless noted.

---

## 📖 Official GitHub resources

| Resource | What it's for |
|----------|---------------|
| **GitHub Docs** <https://docs.github.com> | The official reference for every feature |
| **GitHub Desktop docs** <https://docs.github.com/en/desktop> | Every button in GitHub Desktop, explained |
| **GitHub Skills** <https://skills.github.com> | Free, interactive courses that run inside real repositories |
| **GitHub Community** <https://github.com/orgs/community/discussions> | Ask questions and read answers |
| **GitHub Blog** <https://github.blog> | News, new features, and tips |
| **GitHub Status** <https://www.githubstatus.com> | Is GitHub itself having trouble? |
| **GitHub Education** <https://education.github.com> | Free benefits and resources for students and teachers |
| **GitHub Classroom** <https://classroom.github.com> | Tools for teachers handing out assignments |
| **GitHub Guides** <https://github.com/github/docs> | The docs themselves are open source: you can read (and fix!) them |

## 🎓 Free courses and learning

- **GitHub Skills** (above): start with "Introduction to GitHub", then "Communicate using Markdown", "Review pull requests", and "Contribute to open source".
- **freeCodeCamp** <https://www.freecodecamp.org>: free lessons, with Git and GitHub tutorials alongside web basics.
- **The Odin Project** <https://www.theodinproject.com>: a free, project-based web curriculum that teaches Git early.
- **Coursera, edX, and Khan Academy:** search for "Git and GitHub for beginners." Many courses are free to audit.
- **YouTube:** search "GitHub Desktop tutorial" or "GitHub for beginners." Look for videos made in the last year or two, so the screens match.

> 🔎 **Check the date.** GitHub's screens change. A tutorial from several years ago might show a different layout. The ideas still apply.

## 📚 Reference books and guides

- **Pro Git**, by Scott Chacon and Ben Straub, free at <https://git-scm.com/book>. A deep, friendly book about Git itself. Read it when you're curious about what happens under the hood.
- **Markdown Guide** <https://www.markdownguide.org>: a clear reference for every Markdown feature.
- **GitHub Flavored Markdown spec** <https://github.github.com/gfm/>: the precise rules, for the very curious.
- **Choose a License** <https://choosealicense.com>: plain-language help picking an open-source license.
- **Open Source Guides** <https://opensource.guide>: how to start, run, and join open-source projects.
- **Keep a Changelog** <https://keepachangelog.com>: a nice way to record what changed in each version.

## 🤝 Find a community

| Where | What you'll find |
|-------|------------------|
| **GitHub Discussions** on projects you use | Friendly Q&A with maintainers |
| **Local meetups** (search "your city + GitHub or open source meetup") | People to learn alongside |
| **Hacktoberfest** (every October) <https://hacktoberfest.com> | A month that encourages first contributions |
| **First Timers Only** <https://www.firsttimersonly.com> | Projects set aside for newcomers |
| **Good First Issue** <https://goodfirstissue.dev> and **Up For Grabs** <https://up-for-grabs.net> | Searchable beginner tasks |
| **Discord and Slack communities** for tools you use | Real-time chat |
| **Stack Overflow** <https://stackoverflow.com> (tag `github` or `git`) | Answers to specific questions. Search before asking. |
| **Reddit communities** like r/github and r/learnprogramming | Peer support |

When joining any community: **read the rules**, **search before you ask**, and **say thank you**.

## 🧭 Choose your next adventure

### If you loved **writing and documentation**
- Follow Chapter 21 to write a full project.
- Contribute to documentation of tools you love. Writers are always needed.
- Try **translation** projects.

### If you loved **design and the web**
- Learn **HTML and CSS** (freeCodeCamp, The Odin Project, MDN).
- Build a portfolio with GitHub Pages (Chapter 19) and keep improving it.
- Contribute designs, icons, and accessibility fixes to open-source projects.

### If you loved **organizing and teamwork**
- Run a project board for a club or team (Chapters 9 and 20).
- Become a **maintainer**: triage issues, review pull requests, and welcome newcomers.

### If you're curious about **code**
- Start with **Python** or **JavaScript** with a free beginner course.
- Keep using GitHub Desktop for your projects. The workflow doesn't change.
- When you're ready, explore the **command line**: <https://git-scm.com/book> and GitHub's "Git cheat sheet" are good places to start. Everything you learned about commits, branches, and pull requests carries over exactly.

### If you're curious about **automation**
- Explore **GitHub Actions** (Chapter 15) and the **Marketplace**.
- Search "GitHub Actions starter workflows."

### If you're curious about **security**
- Read GitHub's **Security** docs and turn on every protection for your repos (Chapter 16).

## 🧠 Asking for help the right way

Whether you ask a person or an AI (Chapter 17), a good question gets a good answer. Include:

1. **What you were trying to do.**
2. **What you clicked,** step by step.
3. **What you expected,** and **what happened instead.**
4. **The exact message** (copy the text, or add a screenshot, with private details hidden).
5. **Your setup:** Windows or Mac, GitHub Desktop or the website.

A good question title: *"GitHub Desktop says 'push rejected' after I click Push origin (Windows)."*

## 🪴 Keep growing

- **Make something small every week.** Tiny projects teach more than big plans.
- **Teach someone.** Explaining Git to a friend locks it in.
- **Read other people's repositories.** Open a project you admire and look at how they organize things.
- **Be patient.** Everyone you admire was once a beginner who felt lost.
- **Look after yourself.** Take breaks, sleep, and don't compare your chapter 1 to someone's chapter 20.

## 🎉 One last thing

You started this guide not knowing what a commit was. Now you can create projects, collaborate, review, publish websites, and contribute to open source. That's not a small thing. Welcome to the community.
